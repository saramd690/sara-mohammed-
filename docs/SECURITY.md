# الأساس الأمني

## الهوية
تتم إدارة كلمات المرور وتأكيد البريد واستعادة الحساب وتدوير رموز التجديد بواسطة Supabase Auth. لا يتم تخزين كلمة المرور أو Refresh Token الخام في جداول التطبيق.

## الصلاحيات
الأدوار: candidate وcompany وrecruiter وadmin. الدور الافتراضي للحساب الجديد candidate. لا تُقبل الأدوار من بيانات التسجيل أو user_metadata لاتخاذ قرار أمني.

## RLS
كل جداول public عليها RLS. المستخدم يقرأ ملفه وأدواره وجلساته فقط. جداول auth_attempts وrefresh_tokens محجوبة عن anon وauthenticated عمدًا ولا تملك سياسات قراءة أو كتابة.

## فجوات قبل الإنتاج
1. لا تزال خدمة تسجيل محاولات الدخول وتحديد المعدل غير منفذة على مستوى التطبيق؛ حدود Supabase Auth وحدها لا تغطي كل متطلبات منع التخمين المخصصة.
2. جدول sessions لم يُربط بعد بأحداث الدخول والخروج وتجديد الجلسات.
3. لا توجد واجهة إدارية لإسناد الأدوار؛ لا تمنح admin مباشرة من SQL للمستخدمين النهائيين.
4. يلزم ضبط SMTP وSite URL وRedirect URLs وسياسات كلمات المرور من لوحة Supabase.
5. يلزم إجراء مراجعة RLS واختبارات تكامل في بيئة staging قبل الإنتاج.
